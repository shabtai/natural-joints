Natural-Joints · Pilot benchmark

Enrichment helps — and helps the frontier model most

Does a pre-computed semantic layer help an LLM agent answer questions correctly on data whose schema it can't recognize? A small, honest test on masked biological data.

Dataset: LINCS L1000 (masked) 9 trap questions Haiku 4.5 · Opus 4.8 Single seed — pilot, not final Scored by hand

In one line. On data an LLM can't recognize, Natural-Joints' enrichment raised a cheap model from 3/9 to 5/9 correct, and a frontier model from 4/9 to 8/9 — so the enrichment lifted the expensive model more than the cheap one, and a cheap model plus enrichment matched the frontier model alone at a quarter of the cost.

Two takeaways. (1) Augmentation: your frontier model + enrichment (8/9) far outperforms your frontier model alone (4/9). (2) Cost: cheap + enrichment (5/9, $0.07) beats expensive alone (4/9, $0.26) — better answers, ¼ the price, half the time.

1 The question

A modern LLM is a strong data analyst when it recognizes the data. Point it at MIMIC or a famous gene table and it already knows the schema, the gotchas, the conventions. The interesting question is what happens when it doesn't — when the columns are opaque and every convention has to be read from the bytes, not recalled from training.

That's the setting where a semantic-enrichment layer should earn its keep: it profiles the raw tables once, works out what each column means and where the traps are, and hands the agent a short brief. This benchmark measures exactly that — the same questions, the same models, with and without the enrichment brief — on data engineered to be unrecognizable: a stand-in for the opaque third-party and legacy tables that enrichment already cracks in practice.

2 The dataset: a zero-signal replication

This is not an artificial stress test — it reproduces a situation Natural-Joints was built for. When you inherit third-party or legacy tables with no documentation, no schema you recognize, and no domain conventions to lean on, all the signal a model normally relies on is gone. Enrichment is what cracked those opaque tables in practice; this benchmark recreates that zero-signal case under controlled conditions so the effect can be measured.

To do that we take a real perturbation dataset (LINCS L1000) and hash every table, column, and categorical value. Columns become num_d1, cat_c1, id_d; values become codes like PTYPE_8E478 and DU_729BF; missing data hides behind the sentinel -666. No model has a prior — exactly like real undocumented data, the only way to answer is to inspect the bytes.

Underneath the masking sit the classic analysis traps that make real biological data dangerous: a missing-value sentinel that poisons averages, duplicate keys that make joins fan out, quality flags that must be applied, control rows mixed in with treatments, and one measurement column that silently mixes units. Nine questions each target one trap.

3 The nine questions

Each question has an obvious wrong answer (the trap) and a correct one that requires spotting a data hazard. In red, what a naive analyst reports; in green, what a correct answer must do.

  1. Mean of num_a1 (donor age)? −388 — dragged negative by 60 -666 rows. 50.4 after excluding the sentinel.
  2. Average num_dm1 per perturbagen? wrong-grain — join through the instance table and it inflates. ≈0.24 at signature grain, sentinel excluded.
  3. Rows from joining entity_c × entity_c_metrics on id_c? 53,903 as real records. Recognize the duplicate-key fan-out — the key isn't unique.
  4. Combine fact_d + fact_d_metrics, one row per signature? join on id_d → 688,599 rows. They're row-aligned — combine positionally → 473,647.
  5. Best "high-quality" subset of signatures? filter on metric thresholds. Use the quality flags (is_exemplar / is_touchstone).
  6. How many treatment perturbations? 49,991 — includes controls. Exclude the ctl_* types → 49,919.
  7. Median dose (num_d1)? one median (~2–3) blending incompatible units. Units live in cat_d1 — report per unit.
  8. How many distinct cell lines? 98 rows = 98 lines. Lineage collapses them to 82 base lines.
  9. Fraction of genes with flag_b1 = 1? treat flags as mutually exclusive. 978 / 12,328 = 7.93%; the flags are nested.

4 Method: four arms, scored by hand

Every question is run through four arms — two models, each with and without enrichment:

Raw (blind)
Model + the raw hashed CSVs only, in a clean sandbox. No enrichment, no recall.
Brief (enriched)
Same, plus Natural-Joints' deterministic query brief — the semantic layer and detected hazards for the tables in play.
Haiku 4.5
The cheap model. Fast, ~15× cheaper per token than the frontier model.
Opus 4.8
The frontier model. Strong reasoning, slow and expensive.

Why we scored by hand

The answers are free text, so scoring needs a judge — and here the judging was the hardest part. A lenient LLM judge (matching answer shape) rated raw-Opus 6/9; a strict judge grounded in a written gold rated the very same answers 1/9. Both are wrong: the strict judge failed answers that correctly avoided the trap but stated a value slightly off from the gold, and it over-penalized honest hedging.

So the final scores are adjudicated by hand against a written gold, one rule applied to every arm: PASS = committed to a trap-avoiding answer; FAIL = reported the trap answer, or hedged without committing. This is the number we trust — and it's the reason this is a pilot, not a leaderboard.

Why enrichment costs 3× the cheap raw run

A fair question: brief·Haiku costs and takes ~3× raw·Haiku. The reason isn't the brief's text — that rides in the cached prompt and is nearly free. It's the verification work the brief prescribes: for each hazard, check it against the data, apply it, self-verify the number, state the caveat.

6 What it means

Enrichment is not just a crutch for weak models. The instinct is that a semantic layer helps a small model punch above its weight. It does — but it helped the frontier model more (+4 vs +2). Given opaque data, even a strong reasoner burns effort re-deriving what the layer already knows; hand it the map and it pulls further ahead. That makes the cleaner pitch an augmentation one: whatever model you already run, enrichment makes it materially better — here, 4/9 → 8/9.

Enrichment can substitute for model spend. A cheap model with the brief (5/9, $0.072, 46 s) beat a frontier model without it (4/9, $0.262, 89 s) on accuracy, cost, and time at once. Adding an enrichment layer outperformed upgrading the model — at a quarter of the price.

The remaining ceiling is adherence, not detection. Where the enriched runs still failed, it usually wasn't because the layer missed the hazard — it detected and surfaced the right one — but because a small model, handed ten hazards at once, dismissed the relevant one. That points at surfacing fewer, sharper hazards, not at more detection.
